# 模型接入层

- harness 内部统一使用 types.ts 的 Message、Provider、ModelRequest、StreamDelta 和 Usage。厂商协议差异由对应适配器转换。
- 请求组装与响应流解析分别实现。HTTP 使用内置 fetch，CompleteOptions.signal 传到实际请求，onDelta 传到解析函数。
- SSE 的网络分块可能落在字符或事件中间，复用 sse.ts 处理字节流，不假定一次读取就是一个完整事件。
- 增量用于实时显示，complete 返回完整消息。空的文字和推理片段不发显示事件；签名和工具参数仍需完整累积。
- 工具调用片段按协议中的 index 归类，保留调用 id 和工具名；参数拼接完成后再解析 JSON。工具调用开始事件应避免重复发送。
- 正确识别协议结束标记。提前断流、HTTP 错误和服务端错误要报告给调用方，错误信息保留有助于定位的字段。
- 统一用量时区分普通输入、缓存读取、缓存写入和输出。后续用量字段为 null 或 undefined 时，不覆盖已经收到的有效值。
- thinking 的来源、模型和签名应保留；能否回传按适配器的规则处理。请求转换不修改原始消息对象。
- 验证优先复用假模型、注入的 fetch、本地 SSE 服务和原始响应回放。兼容服务的格式差异使用对应样本验证，不把单个服务的行为当成所有服务的规则。
