# Agent 执行与会话

- 主循环只处理请求、工具调用和事件，不直接打印界面。工具实现通过 ToolContext 获取工作目录、权限回调、沙箱配置和中断信号。
- 初始工具权限统一在主循环里检查；工具执行中需要额外权限时调用 context.checkPermission。
- 每个已经接受的工具调用都要有对应结果，包括执行失败、权限拒绝、工具不存在和中断时跳过的调用。达到请求次数上限时也要完成本轮结果收尾。
- 请求模型前、开始工具调用前和等待权限结束后检查中断信号。中断后停止后续请求，返回 aborted，并补齐尚未执行的工具结果。
- delta 事件只用于显示，完整消息通过 message 事件加入历史。不要把半条回复或实时片段当成完整消息持久化。
- 一轮工具结果完整加入历史后再接收排队消息；中断或没有后续请求额度时不取走队列。
- 会话保存全部消息，JSONL 只追加。消息与压缩记录共用写入顺序；一次写入失败要报告给该次调用，后续写入仍可继续。
- 恢复会话时只修复文件末尾未写完的记录，中间损坏应报错。列会话时不修改文件，压缩记录不计入消息数。
- 压缩只改变发送给模型的上下文，保留完整历史。正确区分完整历史下标、保留消息起点和本次压缩时的消息数。
- 系统提示在启动时生成一次，依次加载全局、仓库根目录到工作目录的指令。同一路径去重，文件优先级和截断规则以 system-prompt.ts 为准。
- 子目录指令附到成功的文件工具结果中，随完整结果进入会话。每轮根据实际上下文重建已加载路径，被压缩省略的指令之后可以重新加载。
